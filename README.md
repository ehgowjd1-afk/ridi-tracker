# 리디(RIDI) 트래커

리디북스의 베스트셀러 순위·작품 리뷰·진행 이벤트를 매일 모아서 추적·분석하는 개인 리서치용 도구입니다.

### 👉 사이트: https://ehgowjd1-afk.github.io/ridi-tracker/

- **수집기**: 파이썬 (설치할 라이브러리 없음 — 기본 기능만 사용)
- **자동 실행**: GitHub Actions, 매일 한국시간 **오전 8시 15분** (약 40~50분 소요)
- **웹사이트**: GitHub Pages (`docs/` 폴더)

> **화면 파일을 고쳤다면** `docs/index.html`의 `?v=3` 숫자를 올려주세요.
> GitHub Pages가 파일을 10분간 저장해둬서, 이 숫자를 안 올리면 브라우저가 낡은 화면을 계속 보여줍니다.

> 개인 학습·리서치 목적입니다. 요청 사이에 2초씩 쉬며 하루 한 번만 수집합니다.
> 모은 데이터는 개인적으로만 확인하며, 공개 서비스나 상업적 용도가 아닙니다.

## 웹사이트 화면

| 탭 | 내용 |
|---|---|
| 웹소설 / E북 단행본 / 웹툰 | 각 분류의 랭킹 (순위 기준이 서로 달라 탭을 나눔) |
| 변동 | ▲▼ · 신규 진입 · 순위권 이탈 · 최고 급상승 |
| **키워드** | 고른 시점·랭킹의 TOP N 안에서 어떤 태그가 몇 편에 붙어 있는지 막대로 표시 |
| 이벤트 | 진행 중 이벤트 전체 (종료 임박순) |
| 검색 | 모아둔 작품 전체에서 제목·작가 검색 |

작품을 누르면 순위 추이 그래프, 별점 추이·분포, 태그, 소개, 걸린 이벤트,
리뷰 분석(키워드·긍부정·리뷰 수 추이), 엑셀 내려받기가 나옵니다.

## 폴더 구조

```
ridi-tracker/
├─ scripts/
│  ├─ collect.py          ← 매일 실행되는 수집기 (여기가 시작점)
│  └─ ridi/
│     ├─ config.py        수집 대상·설정값 (카테고리 ID, 요청 간격 등)
│     ├─ client.py        리디 서버에 요청 보내기 (쉬는 시간·재시도 포함)
│     ├─ rankings.py      랭킹 + 작품 정보 정리
│     ├─ events.py        진행 중 이벤트
│     ├─ details.py       태그·키워드, 작품에 걸린 이벤트
│     ├─ reviews.py       독자 리뷰
│     └─ storage.py       파일 저장
├─ docs/                  ← 웹사이트 (GitHub Pages가 이 폴더를 보여줌)
│  └─ data/               수집된 데이터 (날짜별 누적)
├─ .github/workflows/
│  ├─ collect.yml         매일 자동 실행 설정 (오전 8시 15분)
│  └─ catchup.yml         태그 몰아 채우기 (임시 — 아래 설명)
└─ 조사결과.md            리디 사이트를 직접 조사한 기록
```

## 직접 실행해보기

```bash
python scripts/collect.py --quick     # 빠른 확인 (랭킹 6개만, 1분)
python scripts/collect.py             # 전체 수집 (약 10분)
```

주요 옵션

| 옵션 | 설명 |
|---|---|
| `--quick` | 랭킹 6개만 — 동작 확인용 |
| `--skip-reviews` | 리뷰 수집 건너뛰기 |
| `--skip-details` | 태그·이벤트 연결 건너뛰기 |
| `--skip-events` | 이벤트 목록 건너뛰기 |
| `--interval 3` | 요청 간격을 3초로 (기본 2초) |

## 수집 범위

리디는 **연재물과 단행본에 서로 다른 기준**을 씁니다. 리디 화면 그대로 따릅니다.

| 분류 | 리디가 제공하는 기준 |
|---|---|
| 웹소설 · 웹툰 (연재물) | 오늘의 베스트 · 주간 베스트 · 월간 베스트 |
| E북 단행본 | 주간 베스트 · 월간 베스트 · 스테디셀러 |

| 구분 | 대상 | 기간 |
|---|---|---|
| 전체 랭킹 11개 | 로맨스·로판·판타지·BL 웹소설 / 로맨스·로판·판타지·BL e북·라이트노벨 / 웹툰·BL웹툰 | 위 3종 전부 |
| 세부 장르 50개 | 각 장르의 하위 분류 | 위 3종 전부 |

> `BL 웹툰`(4250)에는 하위 장르가 없습니다. 4251·4252를 넣으면 각각
> **전체와 똑같은 목록 / 빈 목록**이 돌아옵니다. 카테고리 번호는 반드시
> https://ridibooks.com/category/list 에서 실제로 확인하고 추가하세요.

각 랭킹 **200위까지** (리디가 공개하는 최대치).

> ⚠️ **'연간(YEARLY)'은 쓰지 않습니다.** 리디 화면 어디에도 없는 기준이고,
> API에 요청하면 단행본의 경우 **주간 순위를 그대로 돌려줍니다**(상위 30위 전부 일치).
> 연간 데이터가 아니라 가짜이므로 되살리지 마세요.

## 데이터가 쌓이는 곳

```
docs/data/
  index.json              날짜 목록·현황 안내판
  latest.json             오늘 랭킹 + 변동(▲▼/NEW/이탈)
  books.json              작품 카탈로그 (검색용)
  daily/YYYY-MM-DD.json   그날의 전체 랭킹 (덮어쓰지 않고 누적)
  history/YYYY-MM.json    순위·별점 추이 (그래프용)
  books/{작품ID}.json     작품 상세 (소개글·태그·걸린 이벤트)
  reviews/{작품ID}.json   리뷰 누적
  events/latest.json      진행 중 이벤트
  events/ended.json       종료된 이벤트 (계속 쌓임)
  tags.json               작품별 태그 모음 (키워드 화면용)
```

### 종료된 이벤트를 모으는 방법

두 곳에서 모아 `events/ended.json`에 계속 쌓습니다.

1. **리디가 알려주는 것** — `status=completed`로 요청하면 과거 이벤트를 줍니다.
   ⚠️ 응답의 `totalCount`는 틀립니다(실제 145건인데 72로 나옴).
   `offset`을 `limit`만큼씩 늘려가며 **빈 페이지가 나올 때까지** 받아야 전부 옵니다.
2. **우리가 매일 모은 기록** — 어제 '진행 중' 목록에 있었는데 오늘 사라진 이벤트는
   종료된 것으로 보고 보관함에 옮깁니다. 리디가 과거분을 언제까지 보여줄지 모르므로,
   이쪽이 시간이 갈수록 더 믿을 만한 기록이 됩니다.

## 태그 몰아 채우기 (catchup.yml)

작품 태그는 상세페이지에서만 나오는데, **상세페이지는 한 장이 900KB**라 많이 열면
리디가 막습니다. 그래서 평소에는 하루 200건만 모읍니다. 키워드 화면을 쓸 만큼
채우려면 한동안 자주 돌려야 해서 만든 **임시** 작업입니다.

- 매시 5분에 실행, 회차당 상세 200건 (요청 간격 4초 → 13분 일하고 47분 쉼)
- `CATCHUP_UNTIL` 날짜(한국시간)가 지나면 아무 일도 하지 않고 끝납니다
- 더 채우려면 그 날짜를 뒤로 미루고, 다 채웠으면 **이 파일을 지우세요**

### 차단(429)을 피하는 규칙 — 실측 기록

2026-08-22에 상세페이지를 2초 간격으로 200건쯤 연속으로 열자 리디가 HTTP 429로
막았고, 재시도가 겹치며 90분 제한에 걸려 **모아둔 500건이 통째로 날아갔습니다.**
그래서 지금은 이렇게 되어 있습니다.

- API 호출은 2초, **상세페이지는 4초** 간격 (`PAGE_INTERVAL_SEC`)
- 한 회차에 상세는 200건까지 (`MAX_DETAIL_FETCHES_PER_RUN`)
- 429를 만나면 90초 쉬고 한 번만 재시도, **연속 3번 막히면 그 회차는 중단**
- 25건마다 파일에 기록하고, 시간이 넘쳐 멈춰도 그때까지 모은 것은 커밋됨
- 리뷰 수집은 상세페이지를 새로 열지 않음 (이미 저장된 작품만 대상)

이 숫자들을 올리면 다시 막힙니다.

## 알아둘 점

- ⚠️ 리디 랭킹 페이지에는 **1위 위에 번호 없는 추천작**이 하나 붙습니다(광고 자리).
  이건 순위가 아닙니다. API는 이것을 `recommended_bestseller`라는 별도 칸에 담아 주고,
  수집기는 `items`만 읽으므로 순위가 밀리지 않습니다. **이 둘을 절대 합치지 마세요.**
- 리디 랭킹은 **200위가 최대**입니다. 그보다 아래 순위는 리디가 공개하지 않습니다.
- **19금 작품**은 로그인 없이도 순위·상세정보가 모두 나옵니다.
- **19금 이벤트**는 목록(제목·기간·설명)까지는 보이지만, 이벤트 상세페이지는 로그인이 필요합니다.
  그래서 작품 ↔ 이벤트 연결은 반대 방향(작품 상세페이지)에서 가져옵니다.
- 자세한 조사 내용은 [조사결과.md](조사결과.md) 참고.
